# jadetitleservices.com

Static site built with Jekyll and hosted on GitHub Pages.

**Every push to `main` goes live** at https://www.jadetitleservices.com within about a minute. Work on a branch and merge when ready.

## Local preview

Needs Ruby (3.x) and Bundler.

```
bundle config set --local path vendor/bundle
bundle install
bundle exec jekyll serve
```

Then open http://127.0.0.1:4000. Analytics only load in production builds (`JEKYLL_ENV=production`), so local previews don't send hits to GA4 or Clarity.

## Where things live

| What | Where |
| --- | --- |
| Phone, email, form endpoint, analytics IDs, founder | `_config.yml` |
| Service names and URLs (fixed wording) | `_data/services.yml` |
| Audience pages | `_data/audiences.yml` |
| Header and footer links | `_data/nav.yml` |
| Page shell (head, header, footer) | `_layouts/default.html`, `_includes/` |
| Meta tags, Open Graph, canonical | `_includes/head.html` |
| JSON-LD (Organization, Person, WebSite, WebPage, Service, BreadcrumbList, FAQPage) | `_includes/schema.html` |
| The approved recommendation quote | `_includes/recommendation.html` |
| Onboarding, re-check and confidentiality wording for service pages | `_includes/how-we-work.html` |

Each page sets its own `title`, `description`, `breadcrumb`, and optionally `service_id`, `page_type` and `faqs` in front matter. FAQs in front matter render both the visible accordion and the FAQPage JSON-LD, so the two always match.

`sitemap.xml` is generated by `jekyll-sitemap`. Old URLs are kept working with `redirect_from` in the new page's front matter (`jekyll-redirect-from`). GitHub Pages cannot send real 301s, so these are instant meta-refresh redirects with a canonical tag, which Google treats as permanent.

Content rules (what may and may not be claimed) are in `PLAN.md` section 2 in the project folder. Read them before editing copy.
